# 기본 라이딩 초대 취소 검증 (2026-11-07)

## 구현 범위

- `POST /api/v1/ride-invitations/{invitationId}/cancel`: JWT 사용자와 초대 생성자 검사, 유효한 시작 전 초대 제거, HTTP 200과 `invitationId`·`CANCELLED` 반환.
- 기존 초대별 잠금으로 시작·취소·수락/거절·재접속 복구·만료 처리를 보호한다. 취소가 먼저 처리되면 이후 요청은 404이며, 시작 커밋이 먼저 완료되면 취소가 404이다.
- `RIDE_INVITE_CANCELLED`를 리더와 전체 초대 대상의 유효한 `/ws/login` 연결로 전송한다. 기존 OnlineUserRegistry의 다중 연결·실패 격리 처리를 재사용한다.
- 취소 재요청과 취소 후 시작·응답은 `INVITATION_NOT_FOUND`이다. 취소 결과는 보관하지 않는다.
- 기존 DB 스키마·Entity 매핑·`spring.jpa.hibernate.ddl-auto=validate` 유지. 취소는 DB 기록을 생성·수정하지 않는다.

## 추가 테스트 (10개)

### Controller 2개

- JWT principal 기반 취소, body 없는 요청, HTTP 200 응답 형식.
- 토큰 누락·잘못된 토큰 401 및 서비스의 403·404 공통 오류 응답.

### Service 및 실제 접속 레지스트리 6개

- 수락·거절·대기 대상 전체 알림, 온라인 여부와 무관한 취소, DB 접근 없음, 재취소·시작·양쪽 응답 차단, 재접속 복구 없음.
- 비생성자·없는 초대·정확히 30분 만료된 초대 거부 및 알림 없음.
- 수락자 없이 취소 가능, 시작 커밋 실패 후 취소 가능.
- 시작 커밋 중 취소 요청이 시작 완료 후 거부되는지 확인.
- 취소 알림 전송 중 시작·응답·재취소·복구 요청을 넣어 후속 메시지와 DB 저장이 없는지 확인.
- 실제 OnlineUserRegistry와 모의 WebSocketSession을 사용해 다중 연결 및 한 연결의 IOException에도 나머지 연결에 알림을 전송하고 정상 연결을 유지하는지 확인.

### 실제 MySQL·HTTP·WebSocket 2개

- 리더·멤버 다중 연결, 수락·거절·대기 상태에서 취소 전달. 취소 권한 및 인증 오류, 응답 JSON, 연결 유지, 재사용 차단, 재접속 시 알림 없음, 세션·주행 기록 미생성 및 그룹 가입 상태 유지 확인.
- 실제 HTTP 시작·취소 동시 요청 중 200 하나·404 하나, 해당 결과에 맞는 알림만 전달되고 DB 세션 수가 일치하는지 확인.
- UUID로 생성한 테스트 계정과 해당 그룹·세션·참여 기록만 기존 정리 절차로 삭제한다.

## 검증 한계

- Android 팝업·버튼·화면 이동은 구현하거나 기기에서 검증하지 않았다.
- 외부 네트워크·부하·장시간 연결 검증은 수행하지 않았다.
- 취소 알림의 오프라인 보관·재전송, 서버 재시작 후 복구는 제공하지 않는다. 연결이 끊긴 멤버의 기존 대기 UI 자동 정리는 보장하지 않는다.
- 404는 취소·시작·만료를 구분하지 못하며 취소 성공으로 간주할 수 없다.
