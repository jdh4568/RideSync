# 로그인 인증 연동 — 2단계

2026-11-07. 승인 범위: OkHttp 추가, 로그인 REST, JWT 암호화 저장, `/ws/login` 연결, 임시 확인 화면 및 로그아웃. 서버 코드·설정·DB는 변경하지 않았다. API 계약은 [서버 명세](../../server/docs/API_SPEC.md)를 참조한다.

## 구현 결정

- OkHttp 4.12.0을 추가했다. 기존 Compose·수동 DI·Repository 구조와 minSdk를 유지한다. HTTP 로그인은 자동 재전송·리다이렉트를 허용하지 않는다.
- `BuildConfig.SERVER_BASE_URL`은 `ridesyncBaseUrl` Gradle 속성에서 생성하며 기본값은 USB 전달용 `http://127.0.0.1:18080`이다. release에서는 HTTPS만 허용한다.
- API 응답 → Keystore AES-GCM 암호화 저장 → WebSocket 인증 연결 완료 순으로 진행한다. 연결 전에는 임시 화면으로 이동하지 않는다. 토큰의 exp는 로컬 만료 예약에만 사용하며 실제 인증은 서버가 수행한다.
- 저장 파일은 `noBackupFilesDir` 아래에 두어 클라우드 백업·기기 이전 대상에서 제외한다. 비밀번호는 저장하지 않는다. 자동 로그인/Refresh Token은 추가하지 않았으며 프로세스 재시작 시 기존 저장 정보를 정리한다.
- 세션은 앱 단위로 1개가 연결을 소유한다. 이전 로그인·연결의 늦은 콜백은 세대 번호로 무시한다. 로그아웃은 네트워크 종료 응답을 기다리지 않고 메모리·화면을 정리하며, 저장 파일과 암호화 키도 삭제한다. 저장 정리에 실패하면 사용자에게 오류를 표시하고 이후 로그인에서도 정리를 재시도한다.
- 재연결은 1·2·4초 간격으로 최대 3회 후 중단한다. 수동 재연결은 기존 유효한 토큰을 사용하며 로그인 POST를 반복하지 않는다. 최초 연결 실패 상태에서는 로그인 취소로 다른 계정을 입력할 수 있다.
- 앱이 백그라운드로 가면 연결·재연결을 중단하고 복귀 시 재접속한다. 구성 변경에 따른 Activity 재생성에서는 연결을 유지한다. 백그라운드 서비스·푸시·초대 UI는 범위 밖이다.
- 서버 Ping에 대한 Pong은 OkHttp가 처리한다. 클라이언트도 30초 Ping으로 끊긴 연결을 감지한다. 초대 등 애플리케이션 메시지는 아직 UI로 처리하지 않고 무시하며, 잘못된 메시지로 앱을 종료하지 않는다.
- 기존 로그인 디자인을 유지하고 실제 진행 상태·오류·연결 재시도/취소를 추가했다. 임시 확인 화면은 실제 닉네임·연결 상태·로그아웃만 표시하고 임시 화면임을 명시한다. 새 화면 Preview는 1개이다.

## 검증 결과

- JVM 테스트: 세션 상태 전환, 중복 로그인 차단, 연결 전 이동 금지, 재연결 횟수 제한, 백그라운드 정리, 늦은 콜백 무시, 로그아웃과 진행 중 로그인 경합, 만료·인증 거절·저장 실패 처리.
- 실제 로컬 소켓을 사용하는 WebSocket 테스트: Bearer 헤더, Upgrade, 서버 Ping에 대한 masked Pong, 잘못된 텍스트 메시지를 받은 뒤에도 연결 처리 지속 확인. Spring 서버·Android 기기를 사용한 테스트는 아니다.
- `:app:testDebugUnitTest :app:assembleDebug :app:lintDebug --offline` 성공. 보완 후 JVM 테스트 총 12개 통과(인증 관련 11개·기본 예제 1개), lint 오류 0개·경고 20개. `git diff --check` 통과.
- 임시 화면 기본 Preview 1개를 추가하고 컴파일을 확인했다. IDE에는 기존 로그인 화면의 오래된 Preview가 표시되어 새 화면 렌더링·시각 검증 완료로 기록하지 않는다.
- 현재 PC의 `127.0.0.1:18080` 로그인 실패 응답 확인을 시도했으나 서버에 연결되지 않았다. 실제 계정은 생성하거나 수정하지 않았다.
- adb 연결 기기가 없으므로 실제 REST 로그인 성공, Android Keystore 저장·삭제, 키보드·생명주기·실기기 재연결, S26+·S10 5G 실행, 외부 네트워크 검증은 미실행이다. JVM 테스트에서 사용하는 저장소는 가짜 저장소이며 Keystore 검증을 대신하지 않는다.
- 회원가입·제품 메인 화면·초대 처리·라이딩·자동 로그인은 구현하지 않았다. 다음 단계로 자동 진행하지 않는다.

## 2단계 재점검 후 보완 (2026-11-07)

- HTTP 200 헤더 수신 후 본문 수신 중 연결 단절·읽기 시간 초과가 발생하면 `INVALID_RESPONSE` 대신 `NETWORK`로 표시하도록 수정했다. JSON·JWT 형식 오류는 기존 분류를 유지한다.
- 로컬 HTTP 소켓으로 본문 중간 종료와 본문 읽기 시간 초과를 각각 재현하는 회귀 테스트 2개를 추가했다. 실제 응답 본문 읽기 경로를 검증하며, Android JSON 파싱·Spring 서버·Keystore·실기기 통합 검증을 대신하지 않는다. 새 라이브러리는 추가하지 않았다.
- README의 이전 `8080`·앱 주소 입력 안내를 현재 `18080`·`ridesyncBaseUrl` 빌드 설정 방식으로 정정했다.
- 주요 코드 구현과 위 자동 검증은 완료했지만 실제 서버·기기에서 로그인부터 로그아웃까지의 통합 검증은 여전히 남아 있다.
