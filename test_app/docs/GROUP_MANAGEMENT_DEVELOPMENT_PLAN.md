# 그룹 관리 화면 개발계획

작성일: 2026-11-17

## 1. 승인 범위와 현재 상태

- 사용자 요청: 메인 → 그룹 관리, 그룹 목록·가입 신청, 그룹 생성 팝업 개발. 기존 인증·세션·재연결·로그아웃 유지.
- 2026-11-17: 계획에서 제안한 정원 제한 방식, 팝업 동작, 수동 새로고침에 사용자 합의 완료.
- **1단계 UI·화면 이동 구현과 자체 검증 완료**(사용자 승인: “1단계 개발 진행해줘.”). 2단계 API 연결과 3단계 후속 실행은 별도 승인 후 진행하며 자동 진행하지 않는다.
- 현재 실기기를 연결할 수 없다. 에이전트는 구현 단계에서 빌드·lint·자동 테스트와 가능한 Preview 렌더링을 수행하고, 실기기 검증은 사용자가 나중에 직접 수행한다.
- 실제 서버 연동은 자동 테스트와 별도로 기록한다. 서버·연결 환경이 준비되지 않으면 미실행 사유를 기록하며 성공으로 간주하지 않는다.
- 서버 코드·설정·DB 변경, 새 라이브러리, 무관한 리팩터링·디자인 변경, 커밋·푸시·브랜치 변경은 범위 밖이다.

- [사용자 제공 생성 링크 250:145](https://www.figma.com/design/vdeCHSAx4g9YRVDcyfF7Sh/RideMate--Copy-?node-id=250-145)는 어두운 배경 레이어다. 상위 [그룹 생성 프레임 244:89](https://www.figma.com/design/vdeCHSAx4g9YRVDcyfF7Sh/RideMate--Copy-?node-id=244-89)에서 전체 팝업을 확인했다.
- 팝업: 그룹 이름, 여러 줄 그룹 설명, 최대 인원, 취소·그룹 생성 버튼. 목록 위에 어두운 배경과 함께 표시한다.

| UI | 서버 명세 참조 |
|---|---|
| 전체 그룹 목록·이름·설명·현재 인원/정원·가입 상태 | 5.1 GET /api/v1/groups |
| 가입 신청·거절 후 재신청 | 5.2 POST /api/v1/groups/{groupId}/join |
| 그룹 생성 | 6.1 POST /api/v1/groups |

API 상세 계약을 이 문서에 복제해 별도로 관리하지 않는다. 구현 시 위 절과 확인한 DTO를 기준으로 한다.

가입 버튼의 결정 순서:

1. APPROVED: 회색 ‘가입됨’, 비활성화.
2. PENDING: 회색 ‘신청중’, 비활성화.
3. 미가입 또는 REJECTED이며 memberCount >= maxMembers: 회색 ‘정원 초과’, 비활성화.
4. 미가입 또는 REJECTED이며 정원 여유: 파란 ‘가입 신청’, 활성화.
5. 알 수 없는 상태는 신청을 차단하고 상태 확인을 안내한다. myRole만으로 가입 여부를 판단하지 않는다.

관련 서버 DTO에서 확인한 입력 조건: 그룹 이름은 필수·100자 이하, 설명은 선택·500자 이하, 최대 인원은 필수 정수·2~50명. 새 중복 이름 제한을 추가하지 않는다.

정원 제한의 합의 및 한계:

- 서버는 가입 신청 시 정원을 검사하지 않고, 가입 승인 시 정원을 검사한다.
- 이번 앱은 마지막 조회 결과의 memberCount >= maxMembers를 기준으로 신청을 차단한다.
- 조회 후 다른 사용자가 승인되어 정원이 차는 경쟁 상황에서도 신청 API는 PENDING을 반환할 수 있다. 서버 수정 없이 신청 시점의 정원 차단을 보장한다고 표현하지 않는다.

## 4. 합의한 화면 이동·상태 처리

- 메인 그룹 관리 버튼으로 진입하고, 상단·시스템 뒤로 가기로 메인 복귀.
- 화면 진입 시 목록 조회. Compose 재구성에 따른 반복 요청은 방지한다. 수동 새로고침을 제공하고 재진입·가입/생성 성공 후 갱신한다.
- 그룹 화면 이동·이탈은 기존 로그인 WebSocket을 생성하거나 종료하지 않는다.
- 생성 팝업은 제출 전에 취소·시스템 뒤로 가기로 닫으며 입력을 초기화한다. 바깥 영역 터치로는 닫지 않는다. 키보드가 열려 있으면 Android의 키보드 닫기 동작을 고려한다.
- 생성 제출 중에는 입력·중복 제출·취소·팝업 닫기를 제한한다. 인증 만료·로그아웃에 따른 전체 화면 종료는 방해하지 않는다.
- 생성 성공 응답 후 팝업을 닫고 완료 안내·목록 재조회를 수행한다. 그룹 상세 등 다른 화면으로 이동하지 않는다.
- 최초 로딩·정상·빈 목록·오류를 구분한다. 최초 조회 오류에는 다시 시도를 제공한다.
- 갱신 실패에는 기존 목록을 유지하고 실패를 안내한다. 갱신 중에는 가입 동작을 제한하며 중복 조회를 막는다.
- 가입 요청 중에는 대상 버튼 진행 상태를 표시하고 같은 요청의 중복 실행을 UI·ViewModel에서 막는다.
- 가입 성공 응답 후 신청중 상태를 반영하고 목록을 갱신한다. 404·409는 안내 후 재조회한다. 갱신 실패를 이미 성공한 변경 요청의 실패로 표시하지 않는다.
- 생성 실패에는 입력을 유지한다. 네트워크·입력·인증·권한·서버 오류를 구분해 한국어로 안내한다.
- 변경 요청의 응답 단절은 자동 재전송하지 않는다. 가입 여부는 목록의 본인 상태로 확인하며, 생성은 목록 재확인을 안내하되 동명 그룹만으로 성공을 확정하지 않는다.
- 로그아웃·만료·사용자 변경 시 그룹 목록·폼·이동 상태를 정리하고 이전 요청의 늦은 응답이 새 세션에 반영되지 않게 한다.
- 필요한 인증 연결은 JWT를 화면 상태에 노출하지 않고 현재 세션의 보호 REST 요청과 401 처리에 한정한다. 저장소 읽기·자동 로그인·토큰 갱신을 추가하지 않는다. 403은 권한 오류로 처리한다.

레이아웃은 가변 너비, LazyColumn, 시스템 인셋과 팝업의 필요한 스크롤·IME 처리를 적용한다. 긴 그룹명·오류 문구에 따라 높이 증가를 허용하고, 목록 마지막 항목이 하단 버튼에 가리지 않게 한다. 터치 대상은 최소 48dp를 확보한다. Figma 프레임 크기·카드 절대 좌표를 화면의 고정 크기로 사용하지 않는다.

## 6. 검증 범위

- UI: 그룹 관리 기본 Preview 1개, 생성 팝업 기본 Preview 1개. 정의만 한 상태와 실제 렌더링 확인을 구분한다. 렌더링 환경을 사용할 수 없으면 사유를 기록한다.
- 빌드·정적 분석: 변경에 맞춰 :app:assembleDebug :app:lintDebug. 자동 테스트는 관련 :app:testDebugUnitTest로 수행한다.
- 의미 있는 자동 테스트: 가입 버튼 상태 판정, 입력 경계, 응답·오류 매핑, 중복 요청 차단, 성공 후 갱신 실패, 응답 단절, 계정 전환 후 늦은 응답 차단, 보호 API 401과 기존 세션 정리 연결.
- 회귀는 변경한 홈 이동과 인증 연결 지점에 한정한다. 이미 통과한 기록은 현재 변경의 영향 여부를 판단해 재사용하며, 새 변경·실패 없이 전체 조합을 반복하지 않는다.
- 실제 서버: 준비된 환경에서 목록·가입·생성 결과를 확인할 경우 자동 테스트와 별도로 기록한다. 서버 기동·데이터 생성 등 실행 내용과 정리 여부를 명시한다.
- 실기기: 현재 연결 불가. 사용자가 나중에 휴대폰 1대에서 모델·OS·연결 방식을 기록하고 진입/복귀, 신청 상태, 정원 비활성화, 생성/취소, 키보드 접근, 세션 유지 및 로그아웃 후 재진입 방지를 확인한다. 자동 테스트 결과로 실기기 성공을 대신하지 않는다.
- 확대 글꼴·추가 기기·다양한 오류 조합은 변경상 필요하거나 문제가 발견될 때만 추가한다.

## 7. 진행·검증·재개 기록

### 0단계 — 2026-11-17

- 승인: 계획의 합의 필요 동작을 제안대로 진행. 에이전트 자체 검증, 실기기는 사용자가 후속 수행.
- 수행: 개발계획 문서 작성. 시작 시 Git 작업 트리는 깨끗했고 계획 문서는 없었다.
- 검증: 문서 내용·상대 참조 경로·Git 변경 범위 확인. 문서만 작성하므로 앱 빌드·lint·테스트·Preview·서버·실기기는 실행하지 않는다.
- 남은 문제: 정원 신청 시점의 경쟁 상황은 서버 계약의 알려진 한계. 자체 검증은 아직 실행 전이며 실기기는 사용자 후속 작업이다.
- **바로 다음 작업: 사용자가 1단계를 승인하면 UI·화면 이동만 구현한다. 2단계 API 연결로 자동 진행하지 않는다.**

후속 단계마다 승인 범위, 완료 지점, 실제 실행한 검증과 결과, 미검증 사유·남은 문제, 바로 다음 작업을 이 절에 짧게 추가한다. 과거 테스트 결과를 새 실행으로 보고하지 않는다.

### 1단계 구현·자체 검증 — 2026-11-17

승인: “1단계 개발 진행해줘.”. 시작 시 Git 작업 트리는 깨끗했으며 0단계 문서는 저장소에 보존되어 있었다.

완료한 변경:

- RideMateApp: 인증된 구성 안에 사용자별 그룹 화면 표시 상태를 두고 메인 ↔ 그룹 관리 이동을 추가했다. 로그아웃·만료 시 기존 로그인 분기를 유지하며 인증된 이동 상태도 제거한다.
- HomeRoute: GROUPS 이벤트만 그룹 관리 진입으로 연결했다. HomeScreen 배치·다른 준비 중 안내와 HomeViewModel의 재연결·로그아웃 동작은 유지했다.
- feature/group/presentation: GroupManagementRoute·Screen·ViewModel·UiState와 GroupCreationDialog를 추가했다. Route는 생명주기를 고려해 상태를 수집하며 뒤로 가기와 시스템 바를 처리한다. 화면 이탈 시 폼을 초기화하고 Activity 재생성 때에는 기존 메모리 폼을 유지하는 방식을 적용했다.
