# 회원가입 화면 및 API 연동 개발계획

작성일: 2026-11-08. 최종 갱신: 2026-11-09. 현재 상태: 3단계 가능한 로컬 검증·문서 정리 완료. 실제 서버·실기기 통합 검증은 환경 미준비로 미실행이며 전체 동작 검증 완료를 의미하지 않는다.

## 1. 승인 범위와 진행 원칙

사용자는 아래 UX와 개발 방향에 동의하고 1·2단계를 승인했으며, 2026-11-09에 “3단계 진행해줘.”로 검증과 문서 정리를 승인했다. 환경 미준비 시 가능한 로컬 검증으로 마무리하되 실제 통합 검증 완료로 표현하지 않는다.

- 로그인 화면의 회원가입 버튼에서 회원가입 화면으로 이동한다.
- Figma 기반 UI, 입력 검증, 아이디·닉네임 중복 확인과 회원가입 API를 구현한다.
- 로딩·오류·중복 제출·늦은 응답을 처리한다.
- 뒤로 가기와 가입 성공 후 로그인 화면 복귀를 구현한다.
- 가입 성공 후 로그인 아이디를 자동 입력하고 완료 안내를 표시한다.
- 자동 로그인은 하지 않는다. 가입으로 JWT 저장이나 WebSocket 연결을 시작하지 않는다.
- 기존 로그인·세션 동작을 유지한다.

서버 코드·설정·DB, 제품 메인 화면, 초대·라이딩 기능, 자동 로그인, 새 라이브러리, 아키텍처 변경은 범위 밖이다. 커밋·푸시·브랜치 변경은 별도 요청 없이 하지 않는다.

### 확인한 기반

- Kotlin / Jetpack Compose / Material 3, 단일 app 모듈, feature-first + MVVM + Repository, AppContainer 수동 DI.
- 기본 패키지 및 applicationId: `com.example.ridemate_api_test`.
- `RideMateApp`은 인증 세션 진입 여부에 따라 로그인 또는 임시 확인 화면을 표시한다.
- 로그인 회원가입 버튼은 `LoginViewModel.requestSignup()`을 통해 준비 중 안내를 표시한다. `presentation/signup`은 아직 자리만 있다.
- 로그인 REST → JWT 암호화 저장 → WebSocket 연결 완료 → 임시 확인 화면 이동이 구현되어 있다.
- `LoginSession`이 앱 단위 로그인·연결·만료·로그아웃 상태를 소유한다.
- `AuthRepository` 및 현재 `AuthApi`는 로그인 기능 중심이다.
- 서버 주소는 `ridesyncBaseUrl` → `BuildConfig.SERVER_BASE_URL` → `ServerEndpoint`로 관리한다. 기본 개발 주소는 USB 전달용 `http://127.0.0.1:18080`이다.
- 기존 OkHttp REST 설정은 연결 10초·읽기 15초·전체 20초 제한과 자동 재전송·리다이렉트 금지이다.
- 서버 `AuthController`, `SignupRequest`, `AuthService`의 회원가입 처리를 확인했으며 검토 시점에 관련 명세와 충돌은 없었다.
- 기존 로그인 자동 테스트·빌드·lint 및 Preview 기록은 위 검증 문서를 참조한다. 이번 문서 작성 과정에서 다시 실행하지 않았다. 실제 서버·실기기 통합 검증은 남아 있다.

## 4. 합의한 사용자 흐름

### 진입과 복귀

1. 로그인 화면에서 로그인 처리·미완료 세션이 없는 경우 회원가입 버튼을 누르면 가입 화면으로 이동한다.
2. 가입 화면의 화살표와 Android 뒤로 가기는 로그인 화면으로 돌아간다. 키보드가 열려 있으면 시스템 기본 동작으로 먼저 닫는다.
3. 가입 화면에서 나가면 가입 비밀번호와 확인 값을 제거한다. 다시 진입하는 가입 화면은 새 폼으로 시작한다.
4. 가입 성공 시 가입 화면을 닫고 로그인 화면으로 복귀한다. 가입한 아이디를 입력하고 로그인 비밀번호는 비운다.
5. ‘회원가입이 완료되었습니다. 로그인해주세요.’ 안내를 한 번 표시한다. 재구성·화면 재생성으로 복귀나 안내가 반복되지 않도록 한다.
6. 자동 로그인·토큰 저장·WebSocket 접속은 실행하지 않는다.

### 가입 요청 중 뒤로 가기 제한

- **최종 가입 POST를 전송하고 응답을 기다리는 동안에만** 화면 화살표와 Android 뒤로 가기로 화면을 이탈하지 못하게 한다.
- 같은 동안 입력, 중복 확인, 가입 버튼을 비활성화하고 진행 상태를 표시한다.
- 응답 성공 시 로그인으로 이동하고, 실패·시간 초과 시 제한을 풀어 수정·뒤로 가기가 가능하게 한다.
- 평소 입력 중이나 중복 확인 중에는 뒤로 가기를 허용한다. 중복 확인 작업은 화면 이탈 시 취소하거나 결과 반영을 무효화한다.
- 키보드 닫기와 화면 이탈 차단의 실제 동작을 구현 후 확인한다.
- 홈 이동·앱 종료까지 막는 기능은 아니다. 클라이언트 요청 취소·프로세스 종료는 서버 가입 취소를 보장하지 않는다.

## 5. 입력 검증과 상태 관리

### 입력값

- 아이디·닉네임은 공백만인 값을 허용하지 않고 각각 최대 50자 조건을 적용한다.
- 비밀번호·확인은 필수이며 서로 일치해야 한다. 비밀번호는 UTF-8 기준 최대 72바이트를 확인한다.
- 서버에 없는 최소 길이·영문 숫자 조합·특수문자 제한을 추가하지 않는다.
- 입력을 임의로 trim하거나 비밀번호를 변환하지 않는다. 검증·중복 확인·최종 제출에 같은 값을 사용한다.
- 오류는 해당 필드에 표시하고 요청 실패 시 입력값을 유지한다. 비밀번호는 디스크·saved-state Bundle·로그에 저장하지 않는다.
- Activity 재생성 중 입력·요청 상태는 ViewModel 메모리에서 유지한다. 프로세스 종료 후 비밀번호나 진행 요청을 복원하거나 자동 재전송하지 않는다.

### 중복 확인

아이디와 닉네임 각각 `미확인 / 확인 중 / 사용 가능 / 사용 중 / 오류`를 관리한다.

- 로컬 검증을 통과한 값만 중복 확인한다.
- 확인 대상 값과 요청 식별 정보를 보관한다. 입력이 바뀌면 기존 확인 결과를 즉시 무효화한다.
- 이전 요청 결과가 늦게 도착해도 수정된 값에 사용 가능 상태를 적용하지 않는다. 값이 바뀌었다가 원래대로 돌아온 경우도 오래된 요청과 구분한다.
- 동일 버튼의 연속 클릭으로 중복 요청하지 않는다. 실패는 사용 가능으로 취급하지 않으며 명시적 재확인을 허용한다.
- 현재 아이디와 닉네임 모두 사용 가능으로 확인되어야 가입할 수 있다. 나머지 입력 검증도 통과해야 한다.
- 중복 확인은 계정 예약이 아니다. 최종 가입 응답을 최종 판단으로 사용한다.

### 가입 상태 및 오류

가입 상태는 기본 입력 상태, 제출 중, 실패, 성공 결과로 구분한다. 제출 시작 시 사용할 입력을 확정하고 중복 제출을 막는다.

| 결과 | 앱 처리 |
|---|---|
| 정상 가입 성공 응답 | 성공 결과를 한 번 전달하고 로그인 화면 복귀 |
| 아이디 중복 | 아이디 확인 결과 무효화 및 해당 필드 안내 |
| 닉네임 중복 | 닉네임 확인 결과 무효화 및 해당 필드 안내 |
| 동시 가입에 따른 일반 중복 오류 | 두 항목을 다시 확인하도록 안내하고 확인 상태 무효화 |
| 비밀번호 불일치·한도 초과 | 해당 입력과 연결된 오류 안내 |
| 기타 입력 오류 | 실패 안내, 입력 수정 가능, 성공 화면 이동 없음 |
| 네트워크·서버·예상 밖 응답 | 유형에 맞는 안내, 입력 유지, 자동 가입 재전송 없음 |

공개 인증 API에는 Authorization 헤더를 보내지 않는다. 에러 본문의 `code`를 해석하여 같은 HTTP 상태의 서로 다른 원인을 구분하며, 알 수 없거나 잘못된 본문도 앱 종료 없이 처리한다.

응답 단절·시간 초과 등으로 서버 처리 여부가 불명확하면 가입 실패로 단정하지 않는다. 가입 여부를 확인하지 못했다는 안내와 로그인 또는 중복 확인을 통한 확인 방법을 제공한다. 중복 확인 결과만으로 해당 계정의 소유권이나 가입 성공을 확정하지 않는다.

| `feature/auth/presentation/login/` | 준비 중 안내를 실제 이동으로 교체, 가입 아이디·완료 안내 반영 |
| `core/designsystem/`, `app/src/main/res/` | 필요한 공통 스타일·일치하는 자산 재사용, 문자열 리소스 |

- 회원가입 Repository는 로그인 세션을 시작하지 않는 독립 동작으로 둔다. `LoginSession`의 로그인·저장·WebSocket 책임은 유지한다.
- 중복 확인 쿼리 값은 OkHttp URL builder 등으로 안전하게 인코딩한다. 서버 주소를 화면에 직접 쓰지 않는다.
- UI에서 네트워크나 저장소를 직접 사용하지 않는다. 재구성으로 요청이 반복되지 않게 한다.
- 로그인 ViewModel이 현재 Activity에 연결되어 있는 점을 고려해 가입 ViewModel의 이탈 시 정리와 재진입 초기화를 명시적으로 처리한다.
- 새 라이브러리 없이 기존 기반으로 구현한다. 불가피하게 추가가 필요하면 사유와 영향부터 설명하고 승인받는다.
