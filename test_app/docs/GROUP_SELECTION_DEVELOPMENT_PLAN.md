# 그룹 선택 화면 개발계획

## 1. 승인 범위와 현재 상태

- 기준일: 2026-11-17.
- 사용자는 개발계획의 선택·재진입 정책과 제안 문구, **0단계 문서화·1단계 UI·화면 이동·2단계 API·상태 연결 실행**을 승인했다.
- 0단계: 완료. 이 문서 작성 및 내용·참조 확인만 수행했다.
- 1단계: UI·화면 이동 구현 및 가능한 자체 검증 완료. 실제 기기 왕복·조작 검증은 미실행이다.
- 2단계: API·상태 연결 구현과 가능한 자동 검증 완료. 실제 개발 서버는 연결 시간 초과로 미검증이다.
- 3단계 자체 점검·인수인계: 미착수·실행 미승인. 자동 진행하지 않는다.
- 현재 메인의 ‘라이딩 시작’은 그룹 선택 화면으로 진입해 소유 그룹을 조회한다. 최초 무선택이며 정상 목록에서 한 그룹을 선택하면 완료 버튼으로 개발 중 팝업을 연다. 예시 그룹은 Preview·자동 테스트에만 있다.

이번 기능의 최종 범위는 **메인 → 그룹 선택 → 한 그룹 선택 → 선택 완료 → 개발 중 팝업**이다. 팝업을 닫으면 그룹 선택 화면에 머무른다.
멤버 조회·선택 화면, 초대, 라이딩 시작 API, 실시간 라이딩은 후속 개발로 남긴다.
서버 코드·설정·DB, 인증·세션·WebSocket 정책, 완료된 그룹·알림 기능, 무관한 디자인·구조는 변경하지 않는다. 새 라이브러리, 커밋·푸시·브랜치 변경도 범위에 없다.

## 2. 확인한 근거와 재사용 범위

이번 계획 수립에서는 [AGENTS.md](../AGENTS.md), [README.md](../README.md)의 구조·실행·연결 정보, [UI 지침](APP_UI_GUIDELINES.md), [서버 API 명세](../../server/docs/API_SPEC.md)의 공통 인증·REST 오류 규칙과 7.2절을 확인했다.
그룹 선택 계획 문서는 기존에 없었다. 과거 로그인·회원가입·그룹·알림 검증 문서와 다른 개발계획 문서는 열지 않았으며, 서버 구현과 DATABASE.md도 추가 확인이 필요하지 않았다.

소스 기준 경로는 `app/src/main/java/com/example/ridemate_api_test/`이다.

| 연결 지점 | 확인 내용과 적용 방향 |
|---|---|
| `app/navigation/RideMateApp.kt` | 인증된 영역에서 메인·그룹 관리 전환. 그룹 선택 목적지를 추가하고 로그아웃 후 인증된 목적지가 남지 않게 유지 |
| `feature/home/presentation/HomeRoute.kt`, `HomeScreen.kt` | `START_RIDE`가 기존 준비 중 팝업으로 연결됨. 그룹 선택 진입 콜백으로 전환 |
| `feature/group/domain/model/Group.kt` | 그룹 ID·이름·설명·인원·정원·가입 상태 모델 재사용 가능 |
| `GroupRepository`, `GroupRepositoryImpl`, `GroupApi`, `HttpGroupApi` | 전체 그룹 조회는 있지만 소유 그룹 조회 메서드는 없음. 기존 계층에 `ownedGroups()`를 추가하고 파싱·HTTP 실행·오류 처리를 재사용 |
| `core/di/AppContainer.kt` | 기존 그룹 Repository와 수동 DI, OkHttpClient 재사용. 선택 ViewModel factory 추가 |
| `core/network/AuthenticatedSession.kt`, `LoginSession.authenticated` | JWT 전달, 401 세션 종료, 세션 변경 후 늦은 응답 차단 재사용. 토큰을 화면 상태에 넣지 않음 |
| `core/network/ServerEndpoint.kt`, 빌드 설정 | `ridesyncBaseUrl` 한 곳에서 주소 관리. 확인 당시 설정은 `http://192.168.0.5:18080`; 실제 서버 접속 가능 여부는 확인하지 않음 |
| 기존 그룹 UI·테마·자산 | `HomeTheme`, `GroupDesign`, `GroupPrimaryButton`, 그룹 오류 문구, 배경·뒤로 가기·인원 아이콘 재사용 후보 |

기존 그룹 관리 카드는 가입 신청 동작을 가진 비공개 컴포넌트이므로 선택용 카드를 별도로 작게 구성한다. 기존 기능을 과도한 옵션으로 일반화하지 않는다.
기존 `Group`에는 `myRole`이 없지만 이번 화면에서 역할별 UI나 클라이언트 필터링이 필요하지 않으므로 같은 목적의 새 모델을 만들지 않는다.

## 3. API와 표시 범위

서버 API 명세 7.2절의 **GET `/api/v1/groups/owned`**를 사용한다. Request body는 없고 기존 보호 REST의 Bearer JWT 인증을 따른다.

- JWT 사용자와 그룹 소유자가 일치하며 해당 사용자가 `APPROVED` 멤버인 그룹만 반환한다.
- ‘내가 가입한 그룹’과 범위가 다르다. `/groups`나 `/groups/my`로 대신 조회해 임의 필터링하지 않는다.
- 응답 필드: `groupId`, `groupName`, `description`, `memberCount`, `maxMembers`, `membershipStatus`, `myRole`.
- `memberCount`는 그룹장을 포함한 승인 멤버 수이며 대기·거절 멤버는 제외한다.
- 서버의 그룹 ID 오름차순을 유지한다. HTTP 200의 빈 배열은 정상 빈 목록이다.
- 401은 기존 세션 종료·로그인 복귀를 사용한다. 403이나 통신 실패를 ‘그룹 없음’으로 바꾸지 않는다.
- 정원이 가득 찼거나 그룹장만 있는 그룹에 이번 선택 단계의 별도 제한을 추가하지 않는다.
- 선택 완료에는 서버 변경 요청이 없다. 멤버 조회나 초대·라이딩 API도 호출하지 않는다.

서버 구현을 새로 실행·검증한 결과가 아니라 명세와 현재 앱 코드에 근거한 계획이다.

## 4. Figma와 UI 구성

- [그룹 선택 Figma 프레임](https://www.figma.com/design/vdeCHSAx4g9YRVDcyfF7Sh/RideMate--Copy-?node-id=235-2658), 노드 `235:2658`의 디자인 컨텍스트와 스크린샷을 확인했다.
- 구성: 풍경 배경, 상단 뒤로 가기·‘그룹 선택’, ‘그룹을 선택하세요.’ 안내, 그룹 카드 목록, 하단 ‘선택 완료’ 버튼.
- 카드: 그룹명, 인원 아이콘과 현재 인원/정원, 설명, 단일 선택 표시. 선택 시 파란 테두리·연한 배경·원형 표시를 적용한다.
- 그룹명·설명·인원은 서버 데이터로 표시하고 Figma 예시 값은 Preview에서만 사용한다.
- 기존 `login_landscape`를 시각적으로 확인했으며 동일 풍경 배경의 재사용 후보이다. 뒤로 가기·인원 아이콘도 기존 자산을 우선 사용하고 구현 단계 렌더링에서 원본과 대조한다. 일치하지 않는 자산만 대상 Figma에서 확보한다.
- 색상·모서리·버튼·타이포그래피는 기존 디자인 시스템을 우선 사용하고 이번 화면에 필요한 차이만 적용한다. Figma의 Roboto 지정과 기존 시스템 기본 글꼴의 차이는 실제 렌더링에서 확인하고 남는 차이를 기록한다.
- Figma 카드 크기는 참고값이다. 전체 화면 고정 크기나 일괄 확대·축소 없이 가변 너비, 필요한 최대 너비 제한, 콘텐츠에 따른 높이와 줄바꿈을 사용한다.
- 목록은 안정적인 그룹 ID를 key로 사용하는 `LazyColumn`으로 구성한다. 하단 버튼 영역과 시스템 인셋을 고려해 마지막 카드도 접근 가능하게 한다.
- 시각적 버튼 높이 43은 최소 터치 영역 기준에 맞춰 48dp 이상으로 조정한다. 카드와 원형 표시의 선택 동작은 중복 실행되지 않게 연결하고 단일 선택 접근성 의미를 제공한다.
- 기본 Compose Preview는 1개만 정의한다. 제품 문구는 문자열 리소스로 관리한다.

## 5. 승인된 동작·상태 정책

### 선택과 화면 이동

- 최초 진입은 무선택이다. 그룹이 한 개여도 자동 선택하지 않는다.
- 선택 상태는 `selectedGroupId` 하나로 관리한다. 다른 카드를 누르면 선택이 교체된다.
- 현재 정상 조회 목록에 존재하는 그룹 하나가 선택된 경우에만 ‘선택 완료’를 활성화한다.
- 완료를 누르면 **“멤버 선택 화면은 개발 중입니다.”** 팝업을 표시한다. 실제 다음 화면으로 이동하지 않는다.
- 팝업을 닫으면 선택을 유지한다. 팝업이 열린 동안 완료 연속 클릭으로 팝업이 중첩되지 않게 한다.
- 팝업이 열려 있을 때 시스템 뒤로 가기는 팝업부터 닫는다. 선택 화면의 상단·시스템 뒤로 가기는 모두 메인으로 복귀한다.
- 화면을 나갔다가 다시 들어오면 새로 조회하고 선택을 초기화한다. 구성 변경에는 진행 중 상태·선택을 유지해 불필요한 재조회를 막는다.

### 조회와 오류

| 상태 | 표시·동작 |
|---|---|
| 초기·조회 중 | 진행 표시. 카드 선택·완료·중복 재시도 제한 |
| 정상 목록 | 실제 서버 목록과 선택 상태 표시 |
| 정상 빈 배열 | 카드 없이 **“그룹장으로 있는 그룹이 없습니다.”** 표시. 완료 비활성화 |
| 조회 실패 | 기존 오류 체계로 네트워크·권한·서버·잘못된 응답 안내, 재시도 제공. 실패를 빈 목록이나 성공으로 표시하지 않음 |
| 재시도 중 | 진행 표시와 중복 요청 차단. 정상 목록 확인 전 완료 불가 |
| 401·세션 종료 | 기존 세션 처리로 로그인 복귀, 목록·선택·팝업 정리 |

불필요한 주기 조회·즉시 무한 재시도·별도 새로고침 기능을 추가하지 않는다. 오류에서 명시적으로 재시도한다.

### 생명주기와 중복 방지

- Route는 생명주기를 고려해 상태를 수집하고 진입 이벤트만 연결한다. Screen은 상태 표시와 콜백 전달만 담당한다.
- ViewModel은 활성 진입 여부와 실행 중 요청을 확인해 재구성·연속 진입·재시도 클릭의 중복 조회를 방지한다.
- 인증된 목적지는 단일 상태로 표현해 그룹 관리와 그룹 선택이 동시에 열리지 않게 한다. 현재 목적지·인증 상태를 확인해 연속 클릭의 중복 이동을 막는다.
- 화면 이탈·로그아웃·사용자 변경 시 요청 취소와 목록·선택·팝업 초기화를 수행한다. ViewModel이 화면 밖에도 남을 수 있음을 고려해 `onCleared`에만 의존하지 않는다.
- 사용자 식별자와 진입 세대를 확인해 취소 이후 늦은 응답의 반영을 막는다. 구성 변경과 실제 화면 이탈은 구분한다.
- 기존 앱 소유 로그인 WebSocket·재연결·로그아웃을 유지한다. 그룹 선택 화면은 새 소켓을 만들거나 WebSocket 재연결마다 조회하지 않는다.
- 화면 상태에 비밀번호·JWT를 저장하거나 로그로 출력하지 않는다.

## 6. 단계별 작업과 완료 기준

### 0단계: 문서화 — 완료

- 합의된 요구사항·API·디자인 대응·정책·단계·검증 범위를 이 문서에 기록했다.
- 코드·서버·실행 설정은 변경하지 않았다.
- 문서 내용·참조를 확인한다. 앱 빌드와 테스트는 실행하지 않는다.

### 1단계: UI·화면 이동 — 구현·자체 검증 완료

- `feature/group/presentation/selection/`에 `GroupSelectionRoute.kt`, `GroupSelectionScreen.kt`, `GroupSelectionViewModel.kt`, `GroupSelectionUiState.kt`를 필요한 책임에 맞춰 추가한다.
- Figma 기반 화면과 선택 카드, 로딩·빈 목록·오류 표시, 단일 선택·개발 중 팝업을 구성한다.
- `RideMateApp.kt`, `HomeRoute.kt`, 필요한 `AppContainer.kt` factory와 문자열 리소스를 연결한다. 메인 진입과 뒤로 가기를 구현한다.
- 이 단계는 API 미연결 상태임을 명시한다. 일반 실행 경로에 샘플 성공 목록을 넣거나 API 미연결을 실제 빈 목록처럼 표시하지 않는다. UI의 정상 목록·선택 표현은 Preview·테스트 상태로 확인하고 실데이터 조회는 2단계에서 연결한다.
- 완료 기준: 기본 Preview 1개 정의, 가능한 실제 렌더링 대조, 선택·팝업 및 메인 왕복 연결 확인, 변경에 맞는 디버그 빌드·lint. 기기에서 실행하지 않은 화면 이동은 UI 실행 검증으로 보고하지 않는다.

### 2단계: API·상태 연결 — 구현·자체 검증 완료

- `GroupApi.kt`, `GroupRepository.kt`, `GroupRepositoryImpl.kt`에 `ownedGroups()`를 추가한다. 기존 그룹 목록 파싱은 필요한 범위에서만 공유한다.
- 기존 `Group`·오류 처리·보호 REST·AppContainer를 재사용하고 선택 ViewModel에 실제 조회를 연결한다.
- 중복 요청 방지, 취소·늦은 응답 차단, 재진입·세션 변경 정리를 구현한다.
- 인터페이스를 구현하는 기존 테스트 대역도 필요한 부분만 갱신한다.
- 완료 기준: 정상·빈 결과·오류·재시도와 선택 조건의 의미 있는 자동 테스트, 로컬 HTTP 계약 테스트, 직접 관련 회귀. 실제 서버 연동은 환경이 준비되어 실행 가능한 경우에만 별도로 확인한다.

### 3단계: 자체 점검·인수인계 — 실행 미승인

- 승인 범위와 구현을 대조하고 남은 문제를 정리한다. 새 변경·실패·미해결 문제가 없으면 이미 통과한 검증을 반복하지 않는다.
- 실제 동작 변경에 맞게 README의 라이딩 시작 안내를 갱신한다.
