# 메인 화면 개발계획

작성일·최종 갱신: 2026-11-16.
현재 상태: 개발 방향 합의 및 0단계 문서 작성 완료. 1~3단계는 미승인·미착수.

## 1. 승인 범위와 진행 원칙

사용자는 메인 화면 개발계획에 동의한 뒤 “좋아. 0단계 문서 작성해줘.”라고 요청했다. 현재 실행 승인은 **0단계 문서 작성에만** 해당한다. 계획 합의를 후속 코드 구현 승인으로 해석하지 않는다.

합의한 개발 방향:

- Figma 기반 메인 화면을 만들고, 기존 로그인·JWT 저장·로그인 WebSocket 최초 연결 완료 후 임시 확인 화면 대신 표시한다.
- 알림은 버튼만 표시하고 누르면 ‘준비 중’ 안내를 제공한다. 실제 알림이 있다는 의미의 빨간 배지는 표시하지 않는다.
- 알림 옆 프로필 이미지와 프로필 버튼은 모두 제외한다.
- 라이딩 시작·그룹 관리는 카드형 버튼과 ‘준비 중’ 안내만 제공한다. 실제 페이지 이동과 서버 동작은 연결하지 않는다.
- 주행 기록과 최근 라이딩에는 임시 데이터를 넣고 작은 ‘임시 데이터’ 안내로 실제 사용자 기록과 구분한다.
- 최근 라이딩 행에는 상세 이동이나 클릭 동작을 추가하지 않는다.
- 기존 수동 재연결과 로그아웃 접근을 유지한다. 로그아웃은 최근 라이딩 아래 보조 버튼으로 배치한다.
- 회원가입 성공 후 로그인 복귀, 자동 로그인 없음, 기존 인증·세션 생명주기를 유지한다.

서버 코드·설정·DB, 신규 라이브러리, 아키텍처 변경, 실제 홈 통계 API 연동, 가입 신청 팝업·실시간 알림, 그룹·라이딩 화면, 프로필 기능은 이번 구현 범위 밖이다. Manifest/Activity 방향 설정, 관련 없는 리팩터링, 커밋·푸시·브랜치 변경은 하지 않는다.

각 단계의 승인 범위만 수행하고 완료 후 보고한다. 다음 단계로 자동 진행하지 않는다.

## 4. UI·상태·화면 이동 결정

### 레이아웃과 자산

- 메인에만 밝은 테마와 Figma 색상을 적용한다. 기존 인증 화면과 앱 전체 테마 정책을 임의로 변경하지 않는다.
- 기존 색상·로고 스타일·자산을 대조하고 정확히 일치하는 것만 재사용한다. 화면 전용 요소는 home presentation에 둔다.
- Figma 배경·아이콘 원본을 로컬 자산으로 사용한다. 임시 URL을 런타임에서 참조하거나 화면 스크린샷을 배경 자산으로 사용하지 않는다.
- 구현 단계에서 자산의 로컬 파일, 사용 위치, 비율·크롭·실제 렌더링을 확인한다. 폰트 대체가 필요하면 차이와 이유를 기록한다.
- 가변 너비, 좌우 여백, 필요한 최대 너비 제한과 하나의 주 세로 스크롤 영역을 사용한다.
- 기본은 두 동작 카드·통계 2열이다. 좁은 가용 공간이나 큰 글꼴에서는 높이 증가·줄바꿈·필요한 세로 배치로 필수 정보와 버튼을 보존한다.
- 배경은 시스템 영역까지 이어질 수 있으나 본문·터치 대상은 인셋 안에 배치한다. Scaffold와 자식의 여백 중복을 피한다.
- 알림 등 터치 영역은 최소 48dp를 확보하고 접근성 설명을 제공한다. 제품 문구는 문자열 리소스로 관리한다.
- 화면 기본 Compose Preview는 1개만 둔다. 태블릿·가로 전용 설계나 기기별 크기 보정은 추가하지 않는다.

### 세션 상태

| 상태 | 처리 |
|---|---|
| 최초 로그인·JWT 저장·최초 연결 진행 | 기존 로그인 화면의 진행·실패·재연결 흐름 유지. 연결 완료 전 메인 진입 금지 |
| 연결 완료 | `enteredSession` 분기를 통해 메인 표시 |
| 메인 진입 후 재연결 중 | 메인 콘텐츠 유지, 간단한 진행 안내 |
| 자동 재연결 실패 | 연결 오류와 수동 ‘다시 연결’ 제공 |
| 만료·인증 거절 | 기존 세션 정리 후 로그인 복귀 |
| 로그아웃 | 기존 Repository 동작으로 메모리·저장 정보·연결 정리 후 로그인 복귀 |
| 백그라운드·전경 복귀 | 기존 Activity·세션 정책 유지. 메인에서 별도 연결 생성 금지 |

로그아웃은 최근 라이딩 아래 보조 버튼으로 제공한다. 화면 재구성·재생성·재진입에 의해 로그인 POST나 WebSocket 연결이 중복되지 않도록 한다. 기존 로그인 화면을 뒤로 가기 대상으로 쌓거나, 로그아웃 후 이전 메인에 돌아갈 경로를 추가하지 않는다.

홈 데이터를 요청하지 않으므로 가짜 데이터 로딩·네트워크 오류 상태는 만들지 않는다. 실제 통신 상태는 기존 세션 상태로 표시하고 임시 통계와 구분한다.

### 코드 책임

| 위치 | 계획한 책임 |
|---|---|
| `feature/home/presentation/HomeRoute.kt` | 생명주기를 고려한 상태 수집, 화면 이벤트 연결 |
| `feature/home/presentation/HomeScreen.kt` | 전달받은 상태 표시·콜백, 준비 중 안내, 기본 Preview |
| `feature/home/presentation/HomeViewModel.kt` | 기존 `AuthRepository` 인터페이스를 통한 세션 상태·재연결·로그아웃 연결 |
| `feature/home/presentation/HomeUiState.kt` | 화면용 임시 통계·목록·세션 표시 상태 |
| `core/di/AppContainer.kt` | 2단계에서 필요한 home ViewModel factory 추가 |
| `app/navigation/RideMateApp.kt` | 2단계에서 임시 확인 화면 대신 `HomeRoute` 연결 |

1단계는 정적 UI·임시 상태 구성까지이며 운영 세션·화면 이동 연결은 2단계에 한다. 파일 구성은 실제 필요에 맞춰 조정하되, 임시 데이터만을 위한 HomeApi·가짜 서버 Repository·빈 usecase 계층은 만들지 않는다. AuthRepository·LoginSession·네트워크·WebSocket의 기존 동작은 유지한다.

## 5. 단계별 수행 계획

### 0단계 — 개발계획 문서화

승인: 2026-11-16 “좋아. 0단계 문서 작성해줘.”

- 합의한 범위·UI·세션·서버 차이·검증·재개 절차를 이 문서에 기록한다.
- 앱 코드·리소스·서버 및 기존 사용자 변경은 수정하지 않는다.
- 문서 참조·내용·Git 변경 범위를 확인한다. 문서 작업만으로 앱 빌드를 실행하지 않는다.

### 1단계 — 메인 UI

승인 상태: 미승인. 진행 상태: 미착수.

- HomeRoute·Screen·ViewModel·UiState의 필요한 UI 기반, 임시 데이터와 자산을 추가한다.
- 알림·라이딩 시작·그룹 관리의 준비 중 안내, 프로필 제외, 임시 데이터 안내를 반영한다.
- 세션 제어 UI의 표시·콜백 자리를 마련하되 실제 인증 Repository 연결과 목적지 변경은 2단계에 수행한다.
- 기존 로그인 목적지와 실제 세션 동작을 유지한다.
- 기본 Preview 1개를 실제 렌더링해 Figma·자산·배치를 확인한다. 좁은 화면·큰 글꼴·긴 문구는 레이아웃에 필요한 조건만 추가 확인한다.
- `:app:assembleDebug :app:lintDebug`와 변경 범위 확인을 수행하고 결과·남은 항목을 기록한다.

### 2단계 — 기존 세션과 메인 연결

승인 상태: 미승인. 진행 상태: 미착수.

- 기존 `enteredSession` 분기를 유지하며 표시 대상을 HomeRoute로 교체한다.
- 기존 AuthRepository로 실제 재연결·오류·로그아웃을 연결하고 AppContainer factory를 구성한다.
- UI에 토큰·네트워크 처리를 넣거나 별도 WebSocket 연결을 만들지 않는다.
- 임시 확인 화면은 일반 로그인 후 진입 경로에서 교체한다. 진단 화면을 별도 제품 메뉴로 추가하지 않는다.
- `:app:testDebugUnitTest :app:assembleDebug :app:lintDebug`를 수행한다. 추가 테스트는 변경된 세션 표시·이벤트 연결에서 필요한 경우에만 작성한다.
