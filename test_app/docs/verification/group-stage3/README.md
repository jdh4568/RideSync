# 그룹 관리 3단계 인수인계

2026-11-17. 사용자 승인: 핸드폰 없이 가능한 자체 점검·인수인계 정리. 실기기는 사용자가 나중에 직접 확인한다.

## 현재 검증 상태

| 구분 | 근거와 범위 |
|---|---|
| 기본 UI | 1단계 390×844dp 기본 Preview 2개 렌더링 결과 재사용 |
| 자동 테스트 | 2단계 JVM/로컬 가짜 HTTP 서버 테스트 51개 통과 결과 XML 보존 확인. 3단계 신규 실행 아님 |
| 빌드·lint | 2단계 최종 디버그 APK와 lint 오류 0개·경고 12개 기록 재사용 |
| 추가 오류 Preview | 3단계에서 이름/최대 인원 오류, 생성 결과 불명확 안내·회색 생성 버튼을 390×844dp 세로 정적 Preview로 확인. 실제 IME/조작 검증과 구분 |
| 실제 Spring 서버 | 로컬 127.0.0.1:18080 및 현재 설정 192.168.0.5:18080 TCP 연결 불가. 실제 API 미실행 |
| 실기기·에뮬레이터 | 이번 단계 실행하지 않음. 아래 절차는 사용자 후속 검증용 |

2단계 자동 검증의 재현 방법은 [검증 자료](../group-stage2/README.md)를 따른다. 변경·실패가 없으므로 동일한 전체 테스트·빌드·lint를 반복하지 않는다.

## 설치와 서버 준비

- 기존 디버그 APK: `app/build/outputs/apk/debug/app-debug.apk`. 2단계 산출물이며 이번 단계에서 새 APK를 만들지 않는다.
- 현재 `gradle.properties`: `ridesyncBaseUrl=http://192.168.0.5:18080`. 서버를 실행하고 이 주소로 휴대폰에서 접근할 수 있는 연결 경로를 준비한다. 현재 PC 주소가 바뀌었다면 속성을 바꾸고 REST·WebSocket을 함께 확인해 다시 빌드한다.
- 같은 Wi-Fi의 LAN 통신 또는 USB 포트 전달 중 실제 사용할 방식을 선택한다. 현재 LAN 주소 설정에 USB 디버깅 연결만 추가해도 통신이 USB 터널로 바뀌지는 않는다.
- USB 터널을 선택하면 `ridesyncBaseUrl=http://127.0.0.1:18080`으로 빌드하고 해당 휴대폰에 `adb reverse tcp:18080 tcp:18080`을 적용한다. 여러 기기 연결 시 대상 시리얼을 지정한다.
- 기존 계정과 검증용 그룹을 사용한다. 성공한 그룹 생성·가입 신청은 실제 서버 데이터에 남으며, 현재 앱에는 삭제·신청 취소 기능이 없다. 서버 코드/DB를 이 문서의 절차만으로 임의 수정하지 않는다.

## 휴대폰 1대의 주요 흐름

| 순서 | 사용자 동작 | 확인할 결과 |
|---|---|---|
| 1 | 기존 계정으로 로그인 후 메인에서 그룹 관리 선택 | 로그인 연결 완료 후 진입. 실제 목록 또는 빈 결과 표시. 장식용 예시 그룹이 실제 목록으로 나오지 않음 |
| 2 | 새로고침, 상단 뒤로 가기, 다시 그룹 관리 진입 | 갱신 완료 후 최신 상태. 메인 왕복 시 로그인/연결을 새로 요구하지 않음 |
| 3 | 신청 가능한 검증용 그룹에 가입 신청 | 응답 전 중복 클릭 제한, 성공 후 신청중·비활성화. 준비된 데이터에 가입됨/신청중/정원 도달 그룹이 있으면 해당 버튼도 비활성화 확인 |
| 4 | 생성 팝업에서 입력 후 취소하고 다시 열기 | 팝업만 닫히고 입력 초기화. 바깥 영역 터치로는 닫히지 않음. 시스템 뒤로 가기는 키보드가 열려 있으면 먼저 키보드를 닫고 이후 팝업 닫기 확인 |
| 5 | 빈 이름·최대 인원 1 등 잘못된 입력으로 생성 시도 | 해당 필드 오류 표시, 성공으로 안내하지 않음. 오류·키보드가 있어도 입력란과 버튼에 스크롤로 접근 가능 |
| 6 | 구분 가능한 검증용 이름·최대 인원 2~50·설명 선택으로 생성 | 요청 중 입력/취소/중복 제출 제한. 성공 후 팝업 닫힘·완료 안내·목록 갱신. 새 그룹에서 본인이 가입됨으로 표시 |
| 7 | 메인 복귀 후 로그아웃, 뒤로 가기와 재로그인 | 로그아웃 후 이전 그룹 화면/폼에 접근하지 않음. 재로그인한 계정 기준으로 목록 조회 |

확인할 수 있는 데이터와 기기 1대에서 주요 흐름부터 실행한다. 확대 글꼴·추가 기기·만료 대기·응답 단절 등 전체 조합을 기본 필수 조건으로 늘리지 않는다. 문제가 발견되면 해당 조건만 추가한다.

## 알려진 한계와 오류 안내

- 정원 제한은 마지막 목록 조회의 인원 기준이다. 서버는 가입 신청이 아닌 승인 시점에 정원을 검사하므로 신청 직전에 정원이 바뀌는 경쟁 상황은 앱만으로 보장하지 못한다.
- 생성 결과가 불명확하면 자동 재전송하지 않고 현재 팝업의 생성 버튼을 제한한다. 취소로 닫고 목록을 확인하며, 같은 이름만으로 생성 성공을 확정하지 않는다. 결과를 확인하지 않고 다시 생성하면 중복될 수 있다.
- 가입/생성 성공 후 목록 갱신이 실패하면 성공 안내와 갱신 오류를 구분해 표시한다. 새로고침으로 최신 상태를 확인한다.
- 보호 API 401은 기존 세션 정리와 로그인 복귀로 연결한다. 403은 해당 요청의 권한 오류로 처리한다. 실제 서버·휴대폰에서 이 경로를 실행한 결과는 아직 없다.

## 사용자 결과 전달 양식

```text
기기 모델 / Android 버전:
연결 방식 / 서버 주소:
실행한 순서와 결과:
실패한 동작 / 실제 표시 문구:
재현 순서 / 키보드 등 관련 화면 조건:
미실행 항목:
```

계정 비밀번호·JWT·인증 요청 헤더는 기록이나 캡처에 포함하지 않는다. 사용자 결과가 오면 [개발계획](../../GROUP_MANAGEMENT_DEVELOPMENT_PLAN.md)의 마지막 기록에 실제 확인한 범위만 추가한다.
